# Language: Vietnamese and English

The app opens in Vietnamese and switches to English on request. The code is in `src/js/10-i18n.js`; the built-in strings are in `src/js/03-strings.js`.

## Choosing the language

| Control | Where | Scope | Stored |
|---|---|---|---|
| Language the app opens in | Profile, Settings | Every launch | `localStorage` key `openmakeup.v1.lang`, value `vi` or `en` |
| `VI` and `EN` switch | Header on a phone, rail footer on desktop | The current session | Not stored |

- On load the app uses the stored value when it is `vi` or `en`, otherwise Vietnamese. It does not read the browser locale. If storage is blocked, the app starts in Vietnamese and the Settings choice still applies for the session.
- An older build kept the choice under `bp.defaultLang`. It is read when the new key is empty.
- The header switch does not change the next launch. The URL hash carries an `en` flag while English is on, so reloading the same URL (or sharing it) reopens in English. `#today.en` opens Today in English.

## Functions

| Function | Purpose |
|---|---|
| `t(key, vars)` | UI text for `key` in the current language, with `{var}` placeholders filled. |
| `tn(key, n, vars)` | Like `t`, but uses the singular entry `key + "1"` when `n` is 1 and that entry exists. |
| `dx(kind, vi)` | English for a data word: the entry in `DATA_EN[kind]` for the Vietnamese text when English is on, otherwise the Vietnamese text. |
| `tx(value)` | Picks a language from a `[vi, en]` pair, or returns a plain string unchanged. Used for profile and palette text. |
| `L2(pair)`, `dx2(pair)` | Pick index 0 or 1 of a pair by language. |
| `LV(map)` | Wraps a map of pairs so each lookup returns the text in the current language. The occasion, region and kind label maps use it. |
| `applyI18n(root)` | Fills static markup: `data-i18n` sets the text, `data-i18n-aria` sets `aria-label`. It also sets `<html lang>`. |
| `fmtN(n)` | Formats a number: a decimal comma in Vietnamese, a point in English. |
| `todayLabel(place)` | The date line on Today: `Thứ Ba, 6 tháng 10` or `Tuesday, 6 October`. |

## Strings

All UI text lives in one object, `STR`, as pairs:

```js
"tab.need": ["Cần mua", "To buy"],
"val.first": ["Mua 1 món → đủ đồ cho {n} layout: {names}", "Buy 1 item → {n} layouts covered: {names}"],
```

- A value is `[vi, en]`. An English text that is empty falls back to the Vietnamese one.
- `{var}` is a placeholder. `t("val.first", { n: 2, names: "..." })` fills it. A placeholder with no value stays visible as `{var}`.
- Two placeholders are always available: `{season}` is the season name in the current language and `{name}` is the profile's `name`. Variables you pass override them.
- A singular form that differs lives at `key + "1"`. `tn("sum.miss", 1, ...)` uses `sum.miss1`.
- A key with no entry renders as the key itself, so a gap is easy to see in review.

## Data words

Words that come from data, not from the interface, are not in `STR`. They are Vietnamese in the source and map to English through `dx`.

| Kind | What it translates |
|---|---|
| `fit` | The four fit labels: `Hợp sẵn`, `Đổi màu là hợp`, `Khó hợp`, `Tham khảo`. Built in. |
| `swatch` | Swatch names. Catalogue swatches are registered from their `label_vi` and `label` fields. |
| `label` | Step labels. |
| `area` | Step areas such as the eye or the lips. |
| `step` | Routine step names given as plain strings. |

The Vietnamese value is the stable key; the fit labels in a profile stay Vietnamese in the JSON.

Catalogue research text (`data/layouts-catalog.json`) is English at the source. Vietnamese sits beside it in `_vi` fields: `origin_vi`, `features_vi` (same keys), `key_techniques_vi` (same order), `trend_period_vi` and `originalPalette[].label_vi`. In Vietnamese the app shows the `_vi` value and in English the original; a missing `_vi` falls back to the original.

Layout names keep their community form in both languages and are never translated. Only a name coined in Vietnamese gets an English label, through `nameEn`. Product names, hex codes and terms in other scripts are never translated.

## Profile overrides

A profile adds to or overrides the built-in text; see [profile.md](profile.md).

| Field | Effect |
|---|---|
| `i18n` | `{ "key": [vi, en] }`. Merged into `STR` at start-up. An entry replaces the whole built-in pair. |
| `dataEn` | `{ "kind": { "Vietnamese text": "English text" } }`. Merged into the data maps above, for any kind. |
| `nameEn` | `{ "layout-id": "English name" }`. Merged into the English layout names. |
| Pair fields | Profile text written as `[vi, en]` pairs follows the language switch with no registration. |

## Fallbacks

1. Interface text: `STR[key][language]`, then the Vietnamese text, then the key.
2. Data words: `DATA_EN`, then the Vietnamese value. Never an empty string.
3. Catalogue text: the `_vi` field in Vietnamese, the original in English, the original when `_vi` is missing.
4. Profile pairs: index 1 in English, index 0 when it is empty.

A screen that mixes both languages while text is being translated is acceptable. A machine-translated placeholder is not.

## Key naming

Keys are `area.item`, lowercase with camelCase for the second part, grouped by screen or concept.

| Prefix | Use |

| `shop.`, `need.`, `buy.`, `val.`, `why.`, `near.`, `inv.`, `mine.`, `req.`, `grp.`, `maybe.`, `scope.` | Shopping list, kit, layout block, required colours |
| `st.`, `ready.`, `sum.`, `tag.`, `cat.`, `x.`, `pan.`, `ofin.`, `fin.`, `r.` | Status words, summaries, tags, categories, cross-use rules, pans, finishes, roles |

## Copy conventions

**Vietnamese.**

- Plain, modern Vietnamese, the way a Vietnamese developer site writes. Short sentences, no emoji, no slang, no phrase translated word for word from English.
- Makeup and technical terms stay in English: layout, highlight, undertone, tint, cushion, swatch, finish. Do not coin a Vietnamese word for a standard term.
- Modern tone marks: `hòa`, `khỏe`, `thủy`, `hóa`, `xòe`, `tùy`, `quý`. Not `hoà`, `khoẻ`, `thuỷ`.
- Playful, game-like labels are welcome on a product screen where they fit. Check each coined label before it ships.
- One concept, one term. The same thing under two names is a defect.

**English.**

- Plain British spelling: colour, moisturiser.
- Short, imperative buttons.
- Medical or treatment copy never gives a dose and points to the treating professional.

Fixed terms:

| Concept | Vietnamese | Not |
|---|---|---|
| A makeup look | `layout` | look |
| How well a layout suits the person | `Hợp với bạn` | Độ hợp |
| Fit levels | `Hợp sẵn`, `Đổi màu là hợp`, `Khó hợp`, `Tham khảo` | Hợp tự nhiên |
| The kit the person owns | `Đồ đang có` (the tag is `Đang có`) | Tủ đồ |
| The shopping list tab | `Cần mua` | Giỏ |
| The colour checker | `Kiểm tra màu` | Thử màu |
| Match tiers | `Trùng màu`, `Gần giống – dùng được`, `Lệch màu – cần màu khác`, `Chưa có màu – thêm màu để so` | Gần như y hệt, Khác rõ |
| Undertone | `undertone` | tông nền, gốc da |
| Highlight (the product) and to highlight | `Highlight` as a noun, `bắt sáng` as a verb | Bắt sáng as a noun |
| Contour | `Tạo khối` | contour |
| Blush | `Má hồng` | Phấn má |
| Brows | `Chân mày`, `Mày`, `Chì mày` | Lông mày |
